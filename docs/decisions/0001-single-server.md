# ADR-0001：从单服务器与独立渲染进程起步

日期：2026-11-03。状态：阶段 0 默认决策，尚未实现，可随真实部署条件调整。

## 背景

最终需要部署服务器。初期是单人知识视频制作，必须支持后台导出和重启后保留数据，同时避免让基础建设超过产品需要。

## 决策

采用 Next.js/React/TypeScript 网页与 API，Remotion 共享视频组件，独立 Node.js worker，SQLite 持久任务表及本机持久媒体目录。web 和 worker 同机但独立进程，初始任务并发为 1。所有存储路径与服务地址可配置。

第一版不购买商业编辑器模板，不依赖 Lambda、Redis、Kubernetes 或任意特定云厂商。没有因此断言这些方案不可用；当并发和部署条件要求时再评估。

## 影响

- 操作和部署规模小，具备真实后台任务与存储边界。
- SQLite 只用于同主机，数据库文件不放网络共享卷；实际实现核查 SQLite 驱动与运行时兼容性。
- worker 领取任务和续租需要事务，不能只用内存队列。
- 同一台服务器的故障仍会影响所有服务，须做数据库与文件一致备份。
- 多机部署前迁移到适合并发的数据库、队列及共享对象存储。

## 重新评估条件

需要多机 worker、多人工作空间或持续排队影响使用时，记录测量数据并提出迁移方案。服务器规格不足时，先测量渲染内存、CPU 和磁盘，不凭固定配置承诺实时渲染。
