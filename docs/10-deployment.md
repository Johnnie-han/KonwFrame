# 服务器部署

版本：0.1；日期：2026-11-03。状态：部署设计基线，运行配置及脚本待实现，尚未部署。

## 交付目标

用户通过浏览器访问服务器，完成制作、保存和视频导出。

## 待确定信息

## 起步拓扑

优先设计为 Linux 单服务器：HTTPS 入口反向代理到网页服务，网页服务和独立 Node.js worker 共享数据库及持久媒体目录。worker 不暴露公网端口，渲染浏览器通过内部受控媒体端点取素材。

可以使用 Docker Compose 管理服务，但本阶段不生成无法构建的 Dockerfile 或假启动命令。实际服务器规格确定后再定镜像与资源上限。架构选择见 [ADR-0001](decisions/0001-single-server.md)。

## 配置契约（实现时提供配置示例）

| 配置 | 用途 | 约束 |
| --- | --- | --- |
| PUBLIC_BASE_URL | 浏览器访问域名和外部链接 | 生产为 HTTPS，不硬编码开发地址 |
| INTERNAL_API_URL | worker/渲染浏览器访问媒体服务 | 在部署网络内可达，不接受用户指定任意地址 |
| DATA_DIR | 项目数据库、素材、导出及临时目录的根 | 生产挂持久卷，禁止随发布清空 |
| DATABASE_PATH | SQLite 文件 | 在 DATA_DIR 内，web 与 worker 共享同一个本地文件 |
| RENDER_CONCURRENCY | 同时执行任务数 | 首期默认 1，压测后再调整 |
| RENDER_TIMEOUT_SECONDS | 导出时间上限 | 根据服务器和样例实测配置，不在阶段 0 承诺耗时 |
| MEDIA_PROBE_TIMEOUT_SECONDS | 文件探测时间上限 | 超时标记素材失败，不无限等待 |
| UPLOAD_IMAGE_MAX_MIB | 图片大小上限 | 首版 20，代理与应用限制一致 |
| UPLOAD_AUDIO_MAX_MIB | 音频大小上限 | 首版 100，流式限制避免先读完整文件 |
| SESSION_SECRET | 工作空间身份会话签名 | 服务端密钥，不进入客户端包或日志 |
| RENDER_MEDIA_TOKEN_SECRET | 渲染媒体短期凭证签名 | 只授权任务所需素材，过期时间覆盖有效任务窗口 |

web 和 worker 启动时校验配置、数据目录权限和资源依赖。渲染浏览器、系统库、媒体工具、中文字体在镜像构建或部署准备时完成，不能要求第一次请求临时下载全部依赖。具体命令以届时的锁文件与 [Remotion Docker 文档](https://www.remotion.dev/docs/docker) 为准。

## 持久化与任务恢复

建议 DATA_DIR 下区分 db/、assets/、renders/、tmp/。项目只引用服务端生成的相对存储键。临时输出不作为最终结果；成功后在同一文件系统原子移动，发布前不允许下载。

web 启动时将遗留且探测超时的 processing 素材置为 failed。worker 通过租约恢复中断状态；过期 running 任务标记 failed/RENDER_INTERRUPTED，允许按原快照重试。不能因部署重启重新写入一个同 ID 的不同结果。

## 发布、备份与回滚步骤设计

1. 准备环境、密钥、持久目录和域名，核查浏览器、字体及工具可用。
2. 构建并锁定应用和模板版本，在测试环境验证上传至导出的完整流程。
3. 生产更新前停止接收新导出并等待或明确中断现有任务，备份数据库、素材、导出及模板构建版本。
4. 首期可采用短暂停机一致备份，停止 web/worker 写入后备份 SQLite（包括 WAL 一致性）和关联文件，不能仅复制正在写入的主数据库文件。
5. 执行经过验证的数据迁移，启动服务，检查健康状态和测试项目。
6. 失败时回滚应用与兼容的数据版本；有破坏性迁移时使用完整备份恢复，不将旧应用直接连接到不兼容的新数据。
7. 定期在独立目录恢复备份并重新打开项目，确认文件引用有效。清理不得删除仍被快照引用的素材或构建版本。

这些是运维设计，尚无实际执行记录。命令、备份周期和保留期在部署实施时补充。
